# sqlite-murmur usage: PRAGMAs for every feature

All runtime configuration is plain SQLite `PRAGMA` (plus a few
`murmur_*()` SQL functions for actions). This file lists every pragma,
its values, and when each one takes effect. All names are
case-insensitive, as usual in SQLite.

> Prototype status (from [README.md](README.md)): do not use for
> critical data yet. Note the VFS weakens durability: SQLite may
> report COMMIT before a RocksDB flush completes.

## Opening a database

```c
#include <sqlite_murmur.h>

unsigned char key[32] = { /* your key */ };
sqlite_murmur_config config = {key, 250, 16384, 1};
sqlite_murmur_register(&config);
sqlite3 *db = NULL;
sqlite_murmur_open("database-directory", &db);
/* ... SQL ... */
sqlite_murmur_close(db);
sqlite_murmur_unregister();
```

The `config` fields are the 32-byte key, flush interval (ms, 0 = 250),
VFS cache pages (0 = 16384), and RocksDB WAL sync flag. The key, cache
size, and sync flag are open-time settings; everything else below is a
PRAGMA you can read and change over SQL.

## How the pragmas behave

- `PRAGMA name;` reads, `PRAGMA name=value;` writes. Writes echo the
  effective value back.
- Storage pragmas (`cipher`, `compression`, `flush_interval_ms`,
  `background_threads`, `rocksdb_*`) apply **immediately** to the open
  store, but cannot be set on a read-only connection or (for `cipher`)
  inside a transaction.
- `murmur_*` replication/query/file pragmas persist into the
  `murmur_config` table and are validated on write. Two rules:
  - Set them **outside a transaction**.
  - Set them while replication is **stopped** (`SELECT murmur_stop()`
    first); start with `SELECT murmur_start()` after configuring.
- File/bridge pragmas (`murmur_bridge_*`, `murmur_max_*`,
  `murmur_fetch_*`, `murmur_files_generation`) are **restart-applied**:
  the driver reads effective values at open; edits apply on reopen.
- Unknown `murmur_*` names are rejected (`unknown PRAGMA murmur_...`).
- Every value is capped at 64 KiB and must not contain NUL.

## Encryption

AES-GCM pages, key envelopes, and file objects retain their existing formats
with the AWS-LC provider. Existing databases and file keys need no conversion
or configuration changes. Random key material is generated by AWS-LC.

```sql
PRAGMA cipher;              -- current cipher: aes256gcm (default)
PRAGMA cipher='aegis256';   -- switch cipher (empty DB, outside a txn)
```

- `cipher` accepts `aes256gcm` or `aegis256`. It can only change on an
  **empty database outside a transaction**; afterwards the choice is
  persisted with the store. `aegis256` needs a build with
  `SQLITE_MURMUR_ENABLE_AEGIS256=ON`.
- The 32-byte data key itself comes from `sqlite_murmur_register`, not
  from a pragma, and never appears in SQL text.

Key-envelope (KDF) parameters live in the sealed envelope header, not
in `murmur_config`, and are **write-once**: setting any of them seals
the envelope, and later writes fail with "KDF envelope is sealed".

```sql
PRAGMA murmur_kdf;            -- direct (default) or argon2id
PRAGMA murmur_kdf='argon2id';
PRAGMA murmur_kdf_time=3;         -- 1..32
PRAGMA murmur_kdf_memory_kib=65536; -- 1024..16777216
PRAGMA murmur_kdf_threads=4;      -- 1..32
```

`argon2id` additionally needs a build with the vendored Argon2 unit.
Key rotation and pruning are actions, not pragmas:

```sql
SELECT murmur_key_inventory();  -- envelope JSON: seq, current, keys[]
SELECT murmur_rotate_key();     -- stage a successor key
SELECT murmur_prune_keys();     -- drop retired keys
```

The offline `murmur-admin` tool (`tools/murmur-admin/USAGE.md`) offers
the same operations (`keys`, `rekey`) without opening the database.

## Compression

Storage pages and replication payloads use the same vendored zstd library.
Previously compressed data remains readable; compression settings keep their
existing meaning.

```sql
PRAGMA compression;             -- zstd3 (default)
PRAGMA compression='zstd6';     -- zstd1..zstd22 (max level depends on build)
PRAGMA compression='none';      -- disable
```

The level applies to newly written pages immediately. (There is no
`compression_level` pragma; the level travels inside `compression`.)

## Storage performance and persistence

```sql
PRAGMA flush_interval_ms;       -- background persist cadence, default 250
PRAGMA flush_interval_ms=100;
PRAGMA background_threads;      -- encoder workers, default = CPU count
PRAGMA background_threads=4;    -- 1..256
```

`flush_interval_ms=0` normalizes to 250. The VFS page cache size is
open-time only (the `cache_pages` config field, default 16384).

RocksDB tuning (live, persisted with the store):

| Pragma | Default | Range |
| --- | --- | --- |
| `rocksdb_sync` | from open config | 0 or 1 (WAL fsync per batch) |
| `rocksdb_write_buffer_size` | 64 MiB (RocksDB default) | 65536..2^63-1 |
| `rocksdb_max_write_buffer_number` | 2 (RocksDB default) | 2..2^31-1 |
| `rocksdb_block_cache_bytes` | 32 MiB | 0..2^63-1 (0 disables) |
| `rocksdb_max_background_jobs` | 2 (RocksDB default) | 1..2^31-1 |

Reads report live values from the running RocksDB instance.

```sql
SELECT murmur_compact();  -- force a full-range RocksDB compaction
SELECT murmur_backup('/path/to/backup');  -- online checkpoint + manifest
```

## Plain-SQLite pragmas with murmur rules

- `PRAGMA journal_mode` — must stay `DELETE` (enforced; anything else
  is an error). Journals live in RAM, not on disk.
- `PRAGMA mmap_size` — forced to 0; memory-mapped I/O is unsupported.
- `PRAGMA cache_size`, `page_size`, `synchronous`,
  `PRAGMA integrity_check`, etc. behave as in stock SQLite.

## Replication: identity and networking

TLS uses AWS-LC with the existing certificate, private-key, and CA settings.
Trust checks and deterministic managed primary-key UUIDs are unchanged; existing
peer configuration and managed keys need no migration.

Tables replicate once converted with `SELECT crsql_as_crr('table')`
(or the two-argument form). Configure identity/networking while
stopped, then `SELECT murmur_start()`:

```sql
PRAGMA murmur_group_id='00112233445566778899aabbccddeeff';
PRAGMA murmur_bind='0.0.0.0:7443';
PRAGMA murmur_advertise='db1.example.com:7443';
PRAGMA murmur_bootstrap='["10.0.0.2:7443","10.0.0.3:7443"]';
SELECT murmur_start();
```

| Pragma | Default | Meaning |
| --- | --- | --- |
| `murmur_group_id` | `""` | 128-bit hex (UUID form accepted, dashes ignored) naming the replica group. **Immutable after first start** — changing it later is rejected; use a new database. |
| `murmur_bind` | `0.0.0.0:7443` | Local `IP:port` to listen on. |
| `murmur_advertise` | `""` | Address peers dial (`IP:port` or DNS `host:port`). Empty = do not advertise. |
| `murmur_bootstrap` | `[]` | JSON array (max 4096) of `host:port` peers to join. |
| `murmur_crsqlite_extension` | `""` | Path to the companion crsqlite library (loadable-extension builds only). |
| `murmur_certificate` | `""` | TLS certificate (PEM). Never logged. |
| `murmur_private_key` | `""` | TLS private key. Never logged, never in JSON output. |
| `murmur_ca` | `""` | TLS CA bundle for peer verification. |

Identities are 128-bit hex; the all-zero identity is rejected.

## Replication: membership control

```sql
PRAGMA murmur_allowed_peers='["0011…eeff","1234…abcd"]';
PRAGMA murmur_allowed_networks='["10.0.0.0/8","fd00::/8"]';
```

Both are JSON arrays (max 4096 entries): peer identities (128-bit
hex) and CIDR networks (`192.0.2.0/24` or IPv6). Empty (`[]`, the
default) means unrestricted.

## Replication: which tables and columns replicate

```sql
-- Opt tables OUT (default follows CRR state; missing/true replicates):
PRAGMA murmur_table_replication='{"scratch": false}';
PRAGMA murmur_table_replication='{}';  -- replicate everything (default)

-- Per-column merge policies (flat "table.column" map):
PRAGMA murmur_column_policies='{"scores.points": "Counter"}';
```

`murmur_table_replication` is a JSON object (max 1024 entries) of
table name → boolean. Lookups are case-insensitive; **renames drop
flags**, so re-set after a rename. `murmur_column_policies` maps
`table.column` to exactly one of `Lww`, `Counter`, `Set`, `Min`,
`Max`; unknown policy names are rejected, unknown tables/columns are
inert.

## Replication: writer scheduling and retention

```sql
PRAGMA murmur_writer_local_share=90;   -- 1..99 (%)
PRAGMA murmur_writer_remote_share;     -- read-only: always 100 - local
PRAGMA murmur_writer_max_debt_ms=1000; -- 1..60000
PRAGMA murmur_writer_maintenance_reserve_every=100; -- 1..1000000
PRAGMA murmur_retention_min_kept=1000; -- 1..1000000 versions
PRAGMA murmur_retention_max_offline_ms=604800000; -- 60000..2592000000
PRAGMA murmur_retention_gc=1;          -- 0 or 1
```

`murmur_writer_remote_share` is derived, never assigned (assigning it
is an error).
