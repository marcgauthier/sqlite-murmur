# Ownership event API proposal (slice 4)

The following API is implemented and tested as a draft, pending the
coordinator's signature/schema approval. Native reads, ingest, projection,
UDFs, DDL installation and reduced Owner persistence remain coordinator-owned.

`ownership::Target::new(table, pk, TargetKind)` canonicalizes ASCII identifier
case and preserves the exact native packed PK. TargetKind is Row or
Column(String); a literal `__row__` column, including case variants, is
rejected. Every public encoder/constructor revalidates targets supplied via
public fields. Row and Column targets have distinct canonical encodings.

`Event` contains target, EventKind (Grant with optional Value, or Release),
and optional prior_grant/prior_release EventRefs. Row grants carry no value;
column grants carry a value; release requires a prior grant reference.
References must have the same target. No current event embeds its own stamp.
The host resolves/authenticates references against immutable carrier facts
and enforces that they actually name the expected event kind.

An EventRef is target + origin_register[16] + native row_cl i64 + native
col_version i64 + SHA-256(payload). Explicit lifecycle is necessary because
native column versions can reset after delete/reinsert, including repeated
identical grant payloads. No new sequence, timestamp, actor or clock is
generated by this crate. Native metadata and authenticated origin-register
identity come from the consumer, not untrusted payload assertions.

Public functions:

```text
encode_event(&Event, max_bytes: usize) -> Result<Vec<u8>>
decode_event(&[u8], max_bytes: usize) -> Result<Event>
event_ref(&Event, origin_register: [u8;16], row_cl: i64,
          col_version: i64, max_bytes: usize) -> Result<EventRef>
target_key(&Target) -> Result<Vec<u8>>
verify_target_key(key: &[u8], &Target) -> Result<()>
encode_record(&Event, max_bytes: usize) -> Result<Vec<u8>>
decode_record(key: &[u8], bytes: &[u8], max_bytes: usize) -> Result<Event>
```

Version-one event/record encoding is postcard Envelope{version:u8,event}.
Decoding checks the input byte budget before allocation, version, target
and reference shape, kind/value rules, NaN rejection, and exact canonical
re-encoding. Encoding checks variable-size fields before cloning/serializing
and checks the final byte size. This is not a process-memory bound: caller
buffers, decoded references, encoder scratch and prior facts can coexist.

The target key is `09/bridge/owner-crr/v1/` followed by lowercase SHA-256 hex
of postcard `(VERSION, Target)`. A target key addresses one canonical reduced
state or verifies an event being staged for that target. It does NOT identify
an append-only event. Storing every event under that key would overwrite
release facts and violate the reviewed transport design. encode_record/
decode_record encode an EVENT staging record, not reduced Owner<Stamp> state.
The reduced-owner persistence envelope is still coordinator-owned.

The proposed constant-only carrier schema is:

```sql
CREATE TABLE murmur_owner_events(
 target_table TEXT NOT NULL,target_pk BLOB NOT NULL,
 target_kind INTEGER NOT NULL,target_column TEXT NOT NULL,
 origin_register BLOB NOT NULL,col_version INTEGER NOT NULL,
 row_cl INTEGER NOT NULL,payload_digest BLOB NOT NULL,
 payload BLOB NOT NULL DEFAULT X'',
 PRIMARY KEY(target_table,target_pk,target_kind,target_column,
             origin_register,row_cl,col_version,payload_digest)
) WITHOUT ROWID;
```

Row maps to kind=0,column=''; Column to kind=1,column=canonical name. The
host validates PK fields against the decoded event and native metadata,
creates the table with native CRR registration, filters by the TARGET's A4
flags, prevents user mutation, and retains every accepted event identity.
Payload is the only non-PK column. An empty partial payload is staged, never
treated as an envelope. CREATE_EVENT_SQL executes nothing in this crate.

`NativeStamp::new(target, row_cl, col_version, accepted_blob, site_id,
merge_equal_values, max_bytes)` accepts only observed native metadata and a
canonical same-target BLOB event. It rejects negative lifecycle, nonpositive
column version, or missing site when native site tie-breaking is enabled.
When disabled, sites normalize to None. No lifecycle parity assumption is
made. Getters expose target, row_cl, col_version, accepted_blob, site_id and
merge_equal_values; reference(origin_register) derives its immutable EventRef.

`compare_same_target(&self, &other) -> Result<Ordering>` rejects different
targets or differing tie-break modes. It compares native lifecycle,
column version, exact BLOB bytes, then site only when native mergeEqualValues
semantics enable it. It excludes sender-local db_version/seq and wall time.
The token deliberately has no Ord implementation: callers cannot silently
sort unrelated registers into an invented global order. The existing generic
High/Low helpers need a separately reviewed same-scope rank adapter, not an
unchecked cross-register conversion. All actual metadata reads remain in
the consuming SQLite transaction.

No new crates, configuration options, SQL functions, persistence backend,
sidecar files, row-merge engine or transport are introduced by this slice.
All persistent state belongs in SQLite tables inside the same database.

Current draft tests cover envelope/reference round-trips, row/column key
goldens, reserved-column rejection, truncation/version/trailing bytes,
wrong-target/key binding, byte limits, invalid identities/kinds/references,
native lifecycle/version/BLOB/site ordering, cross-scope rejection, repeated
event identities and lifecycle reset separation. They establish pure API
behavior, not production replay retention or native CRR integration.
